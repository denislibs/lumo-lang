# Lumo — дизайн v1

Дата: 2026-10-31
Статус: утверждён

## Цель

Lumo — функциональный язык общего назначения со статической типизацией и выводом типов,
синтаксисом в стиле Rust/Gleam. Компилятор пишется на Rust и компилирует программы
в JavaScript, который исполняется в Node.

Критерий готовности v1: на Lumo можно написать и запустить многофункциональную программу
в одном файле (алгебраические типы, рекурсия по спискам, pattern matching, пайпы),
получая понятные ошибки компиляции, и поэкспериментировать с ней в REPL.

## 1. Язык

### Пример

```lumo
type Option(a) {
  Some(a)
  None
}

fn find(xs: List(a), pred: fn(a) -> Bool) -> Option(a) {
  match xs {
    [] -> None
    [x, ..rest] -> if pred(x) { Some(x) } else { find(rest, pred) }
  }
}

fn main() {
  let nums = [1, 2, 3, 4]
  nums
  |> list.map(fn(n) { n * n })
  |> find(fn(n) { n > 5 })
  |> debug            // Some(9)
}
```

### Типы

- Встроенные: `Int`, `Float`, `Bool`, `String`, `Unit`, `List(a)`, кортежи `#(a, b, ...)`,
  функции `fn(a, b) -> c`.
- Пользовательские алгебраические типы с параметрами: `type Name(a, b) { Variant(...) ... }`.
  Варианты без полей — константы (`None`). Имена типов и конструкторов — с заглавной буквы,
  переменные и функции — со строчной.
- Вывод типов Хиндли–Милнера (Algorithm W, let-полиморфизм). Аннотации типов на параметрах,
  возвращаемых значениях и `let` необязательны; если указаны — проверяются.
  Переменные типов в аннотациях пишутся строчными буквами (`a`, `b`).
- Классов типов/трейтов нет.

### Выражения и определения

- Верхний уровень файла: только `type`, `fn`, `@external fn`. Точка входа — `fn main()`
  без параметров; её возвращаемое значение игнорируется.
- Всё — выражение. Блок `{ ... }` возвращает значение последнего выражения;
  пустой блок или блок, кончающийся `let`, возвращает `Unit`.
- `let x = expr` — неизменяемая привязка; повторный `let x` затеняет предыдущий.
  `let` поддерживает неопровержимые образцы: `let #(a, b) = pair`.
- `if cond { ... } else { ... }` — выражение, обе ветки одного типа. `if` без `else`
  допустим, только если ветка имеет тип `Unit`; всё выражение тогда имеет тип `Unit`.
- Функции: именованные `fn name(params) -> Ret { body }`, анонимные `fn(x) { x + 1 }`,
  замыкания, рекурсия (в т.ч. взаимная между функциями верхнего уровня).
- Вызов: `f(a, b)`. Частичного применения/каррирования нет.
- Пайп: `a |> f(b, c)` ≡ `f(a, b, c)`; `a |> f` ≡ `f(a)`.
- Доступ к модулям stdlib: `list.map(...)`.
- Комментарии: `// до конца строки`.
- Разделитель выражений в блоке — перевод строки (или `;`). Перевод строки не разделяет,
  если строка кончается бинарным оператором или открытой скобкой, либо следующая строка
  начинается с бинарного оператора (так пишутся многострочные пайпы `|>`).

### Pattern matching

`match expr { pattern -> expr ... }`. Образцы:
литералы (`Int`, `Float`, `String`, `Bool`), переменные, `_`, конструкторы `Some(x)`,
кортежи `#(a, b)`, списки `[]`, `[a, b]`, `[x, ..rest]`.
Охранных условий (`if` в ветке) в v1 нет.

Компилятор проверяет **полноту**: неполный `match` — ошибка компиляции с примером
непокрытого значения. Недостижимая ветка — предупреждение.

### Операторы (по убыванию приоритета)

| Операторы | Типы |
|---|---|
| унарные `-`, `-.`, `!` | `Int`, `Float`, `Bool` |
| `* / %` и `*. /.` | `Int` и `Float` соответственно |
| `+ -` и `+. -.`, `<>` | `Int`, `Float`, конкатенация `String` |
| `< > <= >=` и `<. >. <=. >=.` | `Int` и `Float` |
| `== !=` | любой тип, структурное сравнение (оба операнда одного типа) |
| `&&` | `Bool`, ленивый |
| `\|\|` | `Bool`, ленивый |
| `\|>` | пайп, левоассоциативный |

Сравнение функций через `==` — ошибка времени выполнения (`panic`).

### Ошибки в программах

Исключений нет. Ошибочные результаты — `Result(ok, err)` с вариантами `Ok`/`Error`.
`panic("сообщение")` имеет тип `a` и завершает программу.

### FFI

```lumo
@external("Math.sqrt")
fn sqrt(x: Float) -> Float
```

Тело не пишется, аннотации всех типов обязательны. Компилятор доверяет объявлению.
Строка — JS-выражение, вызываемое с аргументами. FFI — основа реализации stdlib.

### Стандартная библиотека v1

Встроенные модули, доступные без импорта:

- prelude (без префикса): `Option`, `Result`, `print(String)`, `debug(a)` (печатает значение
  в синтаксисе Lumo и возвращает его), `panic`.
- `list`: `map`, `filter`, `fold`, `reverse`, `length`, `append`, `sum`, `range`, `find`,
  `any`, `all`, `zip`, `head`, `tail`.
- `string`: `length`, `concat`, `split`, `join`, `to_upper`, `to_lower`, `trim`, `contains`.
- `int`: `to_string`, `parse` (→ `Option(Int)`), `to_float`, `abs`, `min`, `max`.
- `float`: `to_string`, `parse`, `round`, `floor`, `ceil`, `sqrt`.
- `option`: `map`, `unwrap_or`, `is_some`.
- `result`: `map`, `map_error`, `unwrap_or`, `try` (`fn(Result(a, e), fn(a) -> Result(b, e)) -> Result(b, e)`).

### Вне v1 (сознательно отложено)

- пользовательские модули и `import` своих файлов;
- записи с именованными полями и `value.field`;
- трейты/классы типов;
- каррирование и частичное применение;
- guards в `match`;
- async, изменяемые ссылки.

## 2. Архитектура компилятора

Конвейер из независимых этапов, каждый — функция «вход → выход или список ошибок»:

```
исходник → lexer → Vec<Token> → parser → ast::Module
        → typecheck(env) → (typed::Module, env') → exhaust → codegen → JS
```

Этап выполняется, только если предыдущий завершился без ошибок.

### Файлы

| Файл | Ответственность |
|---|---|
| `src/lexer.rs` | Текст → токены со `Span`; переводы строк как значимые токены |
| `src/ast.rs` | Нетипизированный AST, только данные |
| `src/parser.rs` | Рекурсивный спуск + Pratt для операторов; восстановление после ошибок |
| `src/types/ty.rs` | Представление типов и схем |
| `src/types/env.rs` | Окружение: значения, типы, конструкторы, модули stdlib |
| `src/types/unify.rs` | Унификация (union-find), occurs check |
| `src/types/infer.rs` | Вывод типов, обобщение по уровням |
| `src/typed.rs` | Типизированный AST — единственный вход бэкенда |
| `src/exhaust.rs` | Проверка полноты/достижимости (матрица образцов, Маранже) |
| `src/codegen.rs` | `typed::Module` → JS-строка |
| `src/diagnostics.rs` | `Diag { span, message, labels, notes, hint }`, рендер через `ariadne` |
| `src/repl.rs` | REPL |
| `src/main.rs` | CLI |
| `stdlib/*.lumo` | stdlib на Lumo через `@external`, вшивается `include_str!` |
| `runtime/lumo.js` | JS-рантайм (списки, `$eq`, `inspect`, `panic`) |
| `runtime/repl_host.js` | Хост-процесс Node для REPL |

Ключевой интерфейс: `typecheck(&ast::Module, &Env) -> Result<(typed::Module, Env), Vec<Diag>>`.
Начальное окружение содержит stdlib; REPL переиспользует возвращённое окружение.

Граница фронтенд/бэкенд: бэкенд видит только `typed::Module`.

Зависимости: `ariadne` (диагностика), `rustyline` (REPL), `insta` (dev, снапшоты).
CLI-аргументы разбираются вручную (команд мало). Генераторов парсеров нет.

### CLI

- `lumo check FILE` — проверка без генерации.
- `lumo build FILE [-o OUT]` — JS в `OUT` (по умолчанию `FILE` с расширением `.js`).
- `lumo run FILE` — сборка во временный файл и запуск `node`; код возврата пробрасывается.
- `lumo repl` — интерактивный режим.

Требуется Node ≥ 18 в `PATH`; при отсутствии — понятная ошибка.

### REPL

- Долгоживущий процесс `node runtime/repl_host.js`. Rust шлёт JSON-строки
  `{"code": "..."}`, хост исполняет их в постоянном `vm`-контексте и отвечает
  `{"ok": "<inspect>"}` или `{"error": "..."}`.
- Ввод через `rustyline`: история, многострочный ввод, пока не закрыты скобки.
- Принимаются `fn`, `type`, `let` верхнего уровня (только в REPL) и выражения.
- Окружение типов накапливается; ввод с ошибкой окружение не меняет.
- На выражение печатается `значение : Тип`.
- Команды: `:t EXPR` — тип без исполнения, `:quit`.

## 3. Компиляция в JavaScript

Выход — один самодостаточный ES-скрипт: рантайм + код программы + вызов `main()`.
Сгенерированный код и рантайм не используют API Node (только `console` и стандартный JS),
чтобы позже без переделок добавить браузерную цель (см. бэклог, `lumo/ui`).

| Lumo | JS |
|---|---|
| `Int` | `number`; ограничение: безопасный диапазон ±2⁵³ (документируется) |
| `/`, `%` на `Int` | `Math.trunc(a / b)`, `a % b`; при делителе 0 результат `0` |
| `Float`, `Bool`, `String` | `number`, `boolean`, `string` |
| `Unit` | `undefined` |
| кортеж | массив |
| `List` | неизменяемый связный список `{h, t}`; пустой — синглтон |
| конструктор с полями | `{$: tag, _0: ..., _1: ...}` |
| конструктор без полей | синглтон `{$: tag}` |
| функции, замыкания | JS-функции |
| `match` | цепочка `if` по `$`/структуре; привязки — `const` |
| блок/`if`/`match` в позиции выражения | IIFE; в позиции оператора — обычные statement'ы |
| `==`/`!=` | `$eq` из рантайма (структурно) |
| `@external("X")` | прямой вызов `X(...)` |
| идентификаторы | экранирование зарезервированных слов JS суффиксом `$` |

**Хвостовая рекурсия:** самовызов функции в хвостовой позиции компилируется в цикл
`while (true)` с переприсваиванием параметров. Взаимная хвостовая рекурсия в v1
не оптимизируется (документируется).

**Рантайм** `runtime/lumo.js`: конструкторы списков, `$eq`, `inspect` (печать в синтаксисе
Lumo), `panic(msg, loc)`.

## 4. Ошибки и тестирование

### Диагностика компиляции

- Все ошибки — `Diag` с `Span`, основной меткой, заметками и подсказкой; вывод с подсветкой
  кода.
- Ошибки типов формулируются в терминах программы («аргумент имеет тип Float, а ожидается
  Int»), с подсказками для частых случаев (`+` для `Float` → «используй `+.`»).
- Парсер восстанавливается на границах определений и выражений и сообщает несколько ошибок.
- Неполный `match` — ошибка с примером непокрытого значения (`[_, _, ..]`).

### Ошибки времени выполнения

Только `panic`. Codegen передаёт в `panic` место в исходнике Lumo (`main.lumo:12`);
рантайм печатает `panic at main.lumo:12: сообщение` в stderr и завершает процесс с кодом 1.

### Тесты (TDD)

- Модульные тесты каждого этапа: токены лексера; снапшоты AST (`insta`); выведенные типы
  выражений (`fn(x) { x }` → `fn(a) -> a`); проверка полноты.
- Сквозные golden-тесты: `tests/programs/*.lumo` + `*.out` — собрать, запустить `node`,
  сравнить stdout.
- Тесты диагностики: `tests/errors/*.lumo` + снапшот текста ошибки.
- Тест хвостовой рекурсии глубиной 1 000 000.
- Тесты REPL: сценарий ввода → ожидаемый вывод, включая «ошибка не ломает сессию».

## 5. Бэклог (после v1)

### Альтернативные бэкенды

Подключаются без изменений фронтенда — принимают тот же `typed::Module`.

- **A. Tree-walking интерпретатор.** Прямой обход типизированного AST. Даёт `lumo run`
  и REPL без зависимости от Node. Служит эталонной реализацией семантики: дифференциальное
  тестирование — одна программа через интерпретатор и через JS, вывод должен совпадать.
- **B. Байткод + стековая VM.** Компиляция typed AST в байткод и собственная VM
  (замыкания через upvalue, хвостовые вызовы). В 5–20 раз быстрее интерпретатора;
  убирает зависимость от Node.

### Фронтенд на Lumo: `lumo/ui`

UI-фреймворк в духе Elm Architecture: модель — неизменяемое значение, `update(msg, model)`
возвращает новую модель, `view(model)` возвращает виртуальный DOM, рантайм сравнивает
деревья и патчит DOM. Ложится на Lumo естественнее, чем хуки React: ADT для сообщений,
`match` с проверкой полноты в `update`, никакого скрытого состояния.

Компоненты **без локального состояния** (никаких `useState`): всё состояние живёт в модели
приложения, компоненты только отображают пропсы — принцип Elm.

Без расширения UI пишется обычными функциями:

```lumo
type Msg { Inc  Dec }

fn update(msg, count) {
  match msg {
    Inc -> count + 1
    Dec -> count - 1
  }
}

fn view(count) {
  html.element("div", [], [
    html.element("button", [attr.on_click(Dec)], [html.text("-")]),
    html.text(int.to_string(count)),
    html.element("button", [attr.on_click(Inc)], [html.text("+")]),
  ])
}
```

#### Расширение JSX (`.lumox`)

JSX-разметка и объявление `component` — **необязательное расширение**, а не часть ядра языка.
Оно включается расширением файла `.lumox` (по аналогии с `.js`/`.jsx`); в `.lumo` этого
синтаксиса нет. Реализация — отдельный этап `src/ext/jsx.rs` между парсером и тайпчекером:
парсер разбирает разметку только в режиме `.lumox`, затем проход десахаризации переводит её
в обычный AST ядра. Тайпчекер, проверка полноты и codegen о JSX не знают.

```lumo
component Counter(label: String, count: Int, on_inc: msg, step: Int = 1) {
  <div class="counter">
    <span>{label}: {int.to_string(count)}</span>
    <button on_click={on_inc}>+{int.to_string(step)}</button>
  </div>
}

component Card(title: String, children: List(Html(msg))) {
  <section class="card">
    <h2>{title}</h2>
    {..children}
  </section>
}

fn view(model) {
  <Card title="Счётчики">
    <Counter label="Яблоки" count={model.apples} on_inc={AddApple} />
    <Counter label="Груши" count={model.pears} on_inc={AddPear} step={5} />
    <ul>{..model.items |> list.map(fn(i) { <li>{i}</li> })}</ul>
  </Card>
}
```

Разметка. `<` в начале выражения однозначен: дженерики Lumo пишутся в круглых скобках.

| Разметка | Десахаризация |
|---|---|
| `<div ...>children</div>` | `html.element("div", [attrs], [children])` |
| `name="x"`, `name={e}` | `attr.name("x")`, `attr.name(e)` — опечатка в атрибуте = неизвестная функция |
| `data-*`, `aria-*` | `attr.custom("data-id", "5")` |
| текст | `html.text("...")` |
| `{expr}` | `expr` типа `Html(msg)`; `String` оборачивается в `html.text` |
| `{..list}` | вставка `List(Html(msg))` в дочерние элементы |
| `<>...</>` | фрагмент без обёртки |

Разметка имеет тип `Html(msg)`: обработчик, отправляющий сообщение не того типа, —
ошибка компиляции.

Компоненты:
- `component Имя(пропсы) { тело }` — объявление верхнего уровня, имя с заглавной буквы,
  тело типа `Html(msg)`. Совпадение имени с типом или конструктором — ошибка.
- `<div>` (строчная) — HTML-элемент, `<Card>` (заглавная) — компонент.
- Пропсы именованные, порядок произвольный; пропс без значения по умолчанию обязателен;
  неизвестный или отсутствующий пропс — ошибка с именем и типом пропса.
- Значения по умолчанию: `step: Int = 1`.
- `children: List(Html(msg))` заполняется вложенным содержимым; вложенное содержимое у
  компонента без `children` — ошибка.
- Десахаризация: `component Card` → обычная функция ядра с позиционными параметрами в порядке
  объявления (внутреннее имя, недоступное из кода); `<Card .../>` → её вызов, где пропсы
  переставлены по порядку, а пропущенные заполнены выражениями по умолчанию. Ошибки типов
  в пропсах указывают на исходные места в разметке.

#### Что нужно до начала работ

Модули и `import`, записи (модели приложений), браузерная цель
`lumo build --target browser` (ES-модуль + HTML-страница), эффекты для HTTP/таймеров
(`Cmd`/`Sub` как в Elm). Рендер — свой небольшой virtual DOM в рантайме.

### Язык

- Пользовательские модули и `import` (нужно для `lumo/ui`).
- Записи с именованными полями (нужно для `lumo/ui`).
- Guards в `match`.
- `Int` произвольной точности (BigInt) — если понадобится.
- Оптимизация взаимной хвостовой рекурсии (трамплины).
